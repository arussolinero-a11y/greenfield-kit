## 4. Measured thresholds
If the plan sets numeric thresholds (sizes, tolerances, timings, scores):
- Measure each one against artifacts the human already approved **before** approving this plan. Record the result here.
- If an approved artifact doesn't pass, say what happens: a per-artifact tolerance, a different threshold, or revising the artifact. That's a decision the human approves now, not mid-build.

## 5. Quick probe (optional)
If a contract depends on something nobody has measured (a library's behavior, file sizes, browser support), run a throwaway probe **in the scratchpad**, outside the repo, with no network beyond public packages. Record what it showed, and the contract it fixes.

## 6. Steps that wait for a person
Anything only a person can do (a permission, a real call with their credential, a deploy, a remote migration):
- It **never** lives inside the test suite the gate runs. While pending, the suite stays green.
- It gets a separate closing check (`verify/close-<F-ID>.sh`, exit 0 = done), which the coordinator runs with the output visible before marking the feature done.
- Say how the session ends if the person's step doesn't happen (the feature stays `in_review` with a note).

## 7. Tasks per feature
For each feature: tasks in order, each one ending **green** (gate passes).
- Never leave a failing test between tasks. A test written early for a later task is marked pending with the framework's own "todo" marker, naming that task, and is switched on in it.
